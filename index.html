Who I am

01 / About

I got into scripting because a game I played dropped to nine frames every time a round started, and nobody could tell me why.

The answer was boring. Unmanaged connections, loops running per frame, remotes firing on every input. I fixed it, then kept fixing things for other people, and somewhere along the line it stopped being a hobby.

These days I get called in for the structural work. Someone has a game that behaves with five testers and falls apart with fifty. I read the mess, rewrite the core into something modular, and hand it back documented so the next person is not cursing my name.

Two things I actually care about: code you can still read six months later, and gameplay that feels instant on a phone from 2019.

◈

Modular cores

Object oriented modules with clean boundaries. Pull one feature out and the rest keeps breathing.
⚡

Server authority

Remotes validated, rates limited, state owned by the server. Exploiters get a short and boring session.
◐

Data that survives

Session locked saves with retries, versioning and rollback. Progress does not vanish on a bad shutdown.
◇

Interfaces with weight

Spring based motion, real feedback on every press, menus that feel expensive to touch.

How it goes

02 / Process

01

We talk

You tell me what the game is meant to feel like, not just what it should do. I ask the annoying questions early so nothing gets built twice.

02

I map it

Module layout, data shape, remote list, failure cases. You see the structure and the flat price before a single line exists.

03

I build it

Short cycles, a playable place file at the end of each one. You test it live instead of reading progress updates.

04

You own it

Commented source, a short doc, and a walkthrough call. No black boxes and no permanent dependency on me.

05 / FAQ

What does a job cost +

Scope decides it. A standalone system is a small flat fee, a full framework is a different conversation. Either way you get one number in writing before work starts, and it does not move unless you change the brief.

How fast do you deliver +

A single system is usually a few days. Bigger builds get split into milestones so you always have something playable in hand. I would rather quote honestly and hit the date than promise a weekend and go quiet.

Can you join an existing team +

Yes, and I prefer it. Rojo and Git are normal to me, so are code reviews and matching a style guide that already exists. I do not need to rewrite your project to be useful inside it.

What happens after delivery +

Bugs in code I wrote get fixed free with no time limit. New features are new work. If you want me around for ongoing updates, a monthly arrangement is easy to set up.

Do I get the source +

Always. Full source, commented, plus a short document explaining how the pieces talk to each other. You own it outright and you are never locked to me.
